# ПОДРОБНАЯ ИНСТРУКЦИЯ: что нужно сделать для сдачи практики StudyRoomBooking

## Этап 1. Распаковать проект (5 минут)
1. Скачайте `StudyRoomBooking.zip` и распакуйте, например в `C:\Projects\StudyRoomBooking`.
2. Проверьте, что внутри есть: `manage.py`, `requirements.txt`, `.env.example`, папки `accounts, rooms, bookings, api, config, templates, static, docs, media`.

## Этап 2. Установить программы (1 час, один раз)
1. **Python 3.11+**: https://www.python.org/downloads/ — при установке ОБЯЗАТЕЛЬНО поставьте галочку «Add Python to PATH».
2. **PostgreSQL 15+**: https://www.postgresql.org/download/windows/ — запомните пароль пользователя postgres, порт 5432.
3. **Git**: https://git-scm.com/download/win.
4. Проверка (cmd): `python --version`, `git --version`. psql есть в меню «Пуск» → PostgreSQL → SQL Shell.

## Этап 3. Настроить окружение (10 минут)
Откройте cmd в папке проекта:
```
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```
После активации в начале строки появится `(venv)`.

## Этап 4. Переменные окружения (5 минут)
1. `copy .env.example .env`.
2. Откройте `.env` блокнотом: `SECRET_KEY` — любая длинная строка, `DB_NAME=studyroom_db`, `DB_USER=postgres`, `DB_PASSWORD=ваш пароль postgres`. Остальное не меняйте.

## Этап 5. Создать базу данных PostgreSQL (10 минут)
SQL Shell (psql), пароль postgres:
```
CREATE DATABASE studyroom_db WITH ENCODING 'UTF8' TEMPLATE template0;
```
(Сценарий `docs/sql/create_database.sql` — для демонстрации на скриншоте отчёта Темы 4/5.)

## Этап 6. Миграции и администратор (5 минут)
```
python manage.py migrate
python manage.py loaddata rooms/fixtures/init_data.json
python manage.py createsuperuser
```

## Этап 7. Запустить и проверить сайт (15 минут)
```
python manage.py runserver
```
Проверьте по порядку (скриншоты для отчёта):
1. `/health/` → `{"status":"ok","service":"web"}`; `/api/ping/` → `{"status":"ok","message":"pong"}`.
2. Главная → «Аудитории» → фильтры (корпус/тип/вместимость).
3. Под админом: добавить аудитории и оборудование (например: 101 лекционная на 60 мест с проектором; 201 компьютерная на 15 мест).
4. Зарегистрируйтесь как студент → «Поиск»: дата будущая, 10:00–12:00, вместимость 20, оборудование «Проектор» → должна найтись аудитория.
5. «Забронировать» → бронь со статусом «Ожидает подтверждения».
6. Повторите бронь на пересекающееся время → должно появиться сообщение «Аудитория уже занята…».
7. «Расписание» — фильтры по дате/аудитории; карточка аудитории — занятость на сегодня.
8. Войдите как администратор → «Брони (админ)» → Подтвердить. Проверьте, что вторая бронь на это время блокируется.
9. «Мои брони» → отменить свою бронь → повторить бронь на освободившееся время (должно пройти).
10. «Забыли пароль?» — письмо появится в консоли cmd.
11. В psql: `\c studyroom_db`, `\dt` (таблицы), `\d bookings_booking` — скриншоты.

## Этап 8. REST API в Postman (20 минут) — скриншоты для Раздела 5 отчёта
1. `POST /api/auth/register/` — `{"username":"user1","email":"user1@mail.ru","password":"Strong123pass"}` → **201**.
2. Тот же запрос со слабым паролем «123» → **422**.
3. `POST /api/auth/login/` → **200**, скопируйте `access`.
4. `GET /api/rooms/` — публичный → **200**. `GET /api/rooms/search/?date=2030-06-01&time_start=10:00&time_end=12:00&capacity=20&equipment=1` → **200**.
5. `POST /api/rooms/` с токеном студента → **403**; с токеном админа → **201**.
6. `POST /api/bookings/` (тело: room, date, time_start, time_end, purpose) → **201**; повторно на пересекающееся время → **422**; без токена → **401**.
7. Под вторым пользователем `GET /api/bookings/<id чужой>/` → **403** (IDOR).
8. `DELETE /api/bookings/<id>/` своей брони → **204**.
9. `PATCH /api/bookings/<id>/ {"status":"confirmed"}` под админом → **200**.
